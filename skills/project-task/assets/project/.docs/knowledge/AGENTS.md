# 长期事实维护规则

- 只维护已确认且跨任务有效的事实与决定，例如模块职责、接口、数据约定和研究方法。当前执行对话负责自动更新，无需另行请主对话整理。
- 项目已有 README、接口说明或数据字典足够时，在索引中引用，不复制维护另一份。按主题建立文件，不预建一组空文档。
- 每份文档写明适用范围、有效或已被替代的状态、依据的具体文件或资料版本、核实日期；决定另写理由、适用条件和确认来源。
- 未验证假设和临时排错留在当前 tasks.md；测试结果只证明对应版本，不升级成永久事实。示例中的资料和模拟结果不能写入真实知识。
- 更新前读取现有内容，保留其他任务信息。发现矛盾时记录双方依据，未确认取舍前不覆盖；影响任务验收的冲突阻塞任务，其他冲突列入报告。
- 确认失效的事实及时更新，仍有解释价值的决定标明被哪个新决定替代。不要追加整段试错历史。
- 更新 `.docs/index.md` 的事实入口，并在任务 report.md 中记录本次实际更新。没有新的长期事实就写无需新增。

## 文档最小格式

```markdown
# 主题

- 适用范围：具体模块、数据或任务
- 状态：有效 / 已被替代
- 核实日期：YYYY-MM-DD
- 依据：实际文件、代码或资料版本、用户确认来源

## 已确认内容
有依据的事实；能引用现有文档就不重复全文。

## 关键决定（按需）
选择、理由、适用条件和确认来源。

## 替代关系（按需）
新的决定或文档入口；说明旧内容不再作为当前依据。
```
