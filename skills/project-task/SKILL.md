# Project Task

让设计对话写出可独立实施的当前任务，让新对话只凭任务入口完成工作并自动收尾。所有模板和示例都在本 Skill 内；以下相对资源路径均以本 SKILL.md 所在目录为基准，不能按用户项目目录解析。

## 选择行为

| 用户意图 | 行为 |
| --- | --- |
| 准备任务、整理已确认方案 | 建立或更新任务记录，不实施业务改动 |
| 执行、继续任务，或单独提供一个既有任务目录要求完成 | 核对记录并接管，执行到验收与自动收尾 |
| 为当前任务交接 | 保存实际状态，停止本任务写入 |
| 只读、解释、审查任务 | 只读取并回答，不把路径自动当作实施授权 |

Plan mode 下只整理方案，不初始化目录、不修改任务文件、不实施。说明需要在执行模式中落盘；不能用“只是文档”绕过模式限制。

## 定位项目并接入

1. 以用户指定项目或任务路径定位根目录；任务目录必须对应项目的 `.docs/{task}/`。未提供位置时检查当前工作目录，只有确实有多个目标无法区分才询问。执行路径不存在或缺少 tasks.md 时，说明缺口，不从聊天猜造任务或静默新建另一份。
2. 读取目标项目适用的 AGENTS.md 及覆盖规则，检查已有修改。始终保留原有规则，不修改 Codex home、全局 AGENTS.md、config.toml 或安装 Skill 到其他位置。
3. 对准备或执行请求，首次接入仅补齐缺失文件：从 [项目资产](assets/project/AGENTS.md) 对应目录复制 `.docs/AGENTS.md`、`.docs/index.md`、`.docs/knowledge/AGENTS.md`。已有文件先读，不覆盖；有必要时仅合并本流程缺失的内容，保留原有资料和任务。
4. 项目根 AGENTS.md 不存在时使用 [入口片段](assets/project/AGENTS.md)；存在时追加其中的标记段。标记段或语义等价入口已存在则不重复添加。需要更新片段时只改本流程的段落，保留用户其他约定。若现有规则与本次授权有实质冲突，先说明冲突，不修改全局规则解决它。
5. 明确读取目标项目 `.docs/AGENTS.md`、`.docs/index.md`；写长期事实前再读 `.docs/knowledge/AGENTS.md`。不假设子目录规则会被自动发现。只读和交接请求不顺带重装项目规则。

## 准备任务

- 依据已确认目标和实际项目材料，选择稳定的 `{task}`，建议简短小写连字符名称。初始实施对话建议同名，续接可加“· 续接”；不能设置标题时只建议，不声称已改名。
- 同名目录存在时先读取，明确是否同一任务；用户明确继续同一任务才更新，不能把新目标覆盖进去。不同任务使用不同标识，不改变已有目录。
- 用 [任务模板](assets/task/tasks.md) 生成 `.docs/{task}/tasks.md`，填写目标、范围、当前要求、验收方法、关键决定及来源、材料入口、计划、疑问和维护者。不保留占位文字或虚构事实，不预填验证成功。
- 需求变化替换失效条款，不把废弃方案保留为并列要求。缺少关键决定时记录疑问并询问，不能在“准备”请求中擅自实施。
- 更新索引自己的任务行，返回任务目录、建议对话名及下一步调用：`$project-task 执行 .docs/{task}`。这一阶段不生成 handoff.md 或 report.md。

## 执行与接续

- 阅读 tasks.md 和存在的 handoff.md，按需读取代码与事实来源；不默认读取全部旧任务或整个示例集。
- 核对实际目录、分支、相关文件及未提交修改，不把基准提交号当作完整工作状态。换聊天不迁移文件；缺少另一代码副本中的修改时先解决缺口。
- 同一任务同一时刻只有一个维护者。设计中、待接续且已停止写入的任务可接管；已由其他对话实施中的任务先查明是否仍在写入，不能查明则要求明确交接，不靠旧时间戳假定已停。记录实际维护者及接管时间，不捏造对话 ID。
- 接管后更新任务状态为实施中；存在待接续交接时标为已接续，写接续者和时间。旧验证仅代表记录时状态。
- 自主完成实现、必要验证和修复。只在目标、输出含义、关键设计或授权范围需要决定时请求用户判断；常规实现和文档维护不逐步放行。
- 在有效阶段、重要验证、需求变化或阻塞时更新任务，不记逐工具调用流水账。证据不足写未验证；真实阻碍记录在 tasks.md，不能生成冒充完成的报告。
- 已完成任务重复调用时，核对 report.md 的适用版本与当前文件；没有新要求或差异则返回现有结果，不重复创建或扩展任务。新要求或文件变化使旧结果不再适用时，标明旧报告待复验，再继续工作。

## 交接

使用 [交接模板](assets/task/handoff.md) 写 `.docs/{task}/handoff.md`：引用当前要求，记录实际工作位置、未提交改动、暂停点、阻碍、未验证判断、旧方案残留和下一步。更新任务及索引为待接续，记录原维护者停止写入。再次交接替换当前快照，不追加无限历史；仅为交接请求创建此文件。

## 自动收尾：执行请求的一部分

验收通过后自动完成，不等待第三次 Skill 调用：

1. 用 [报告模板](assets/task/report.md) 生成 `.docs/{task}/report.md`，逐项对应成果、验收方法、实际结果、证据与适用版本，以及变化、限制和长期事实更新。它是任务完成报告，不是研究正文或业务产物；实际成果放在任务约定位置并链接。
2. 更新 tasks.md 为完成，只留简短结论并链接报告；将已完成验收的详细表归入 report.md，避免两份长期重复维护。未完成任务只记录现状和阻碍，不宣称验收通过。
3. 阅读知识规则及相关现有文档，自动维护本任务已核实且跨任务有效的事实、依据和核实日期。没有新事实时在报告写“无需新增”，不创建空知识文档。已有文档足够则引用。
4. 与既有事实或决定冲突时不擅自替换：在任务及报告列明冲突、证据和影响。影响验收的冲突使任务保持阻塞，并将报告明确标为未完成；无关的非阻塞冲突列为限制。不要强行让文档一致来伪造完成。
5. 更新索引自己的任务行及本次事实入口，重读共享文件并保留其他任务的修改；不同代码副本的索引需实际合并。记录 report.md 中的知识更新结果，所有收尾完成才发送最终答复。

最终答复简短说明结果、验证及限制，提供任务完成报告和实际成果入口。任务和报告保留原目录，不自动搬移归档，也不默认提交、推送或发布。

## 需要示例时

只在学习格式或处理相应情形时读取 [示例索引](references/examples/README.md)，再选择 Python CSV 或研究比较示例。四阶段快照仅教学用，演示测试与虚构资料不得复制为项目事实。实际项目只维护一份当前任务记录。
