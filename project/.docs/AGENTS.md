# 项目任务维护规则

本文件约束 `.docs/` 的维护；任务实施仍遵守项目已有规则。先读 index.md，再读当前任务及必要来源，不默认读全部历史。完成后的主对话默认只读 report.md 的成果概述及必要成果、事实入口，不递归读取任务目录；按具体问题再读取详情。

## 职责与当前要求

- `.docs/{task}/tasks.md` 保存当前目标、范围、要求、验收标准、进度和疑问。需求变化替换失效条款，只留影响继续工作的变化说明。
- `{task}` 稳定且唯一，建议小写连字符名称；初始实施对话同名，续接可加后缀，目录不跟随聊天改名。
- 设计对话建立任务，实施对话接管后成为该任务唯一维护者。新决定须明确传递，由当前维护者更新要求和实现；不假设多个聊天自动同步。
- 换维护者前确认原对话已停止写入。不同任务可并行，代码相互影响时使用独立副本并明确传递改动；fork 不会清除旧假设。
- 索引只放任务标识、目标摘要、状态、入口及事实文档入口，不复制正文。各维护者只更新自己的任务行；共享文件串行写入，写前重读保留其他更新，不同副本须汇总合并。

## 更新与验证

- 常规实现、验证、修复和任务文档维护在已授权范围内自主完成。影响目标、关键设计或授权边界的决定才需要询问，不要求每步批准。
- 需求变化、有效阶段完成、重要验证、阻塞、交接和结束时更新，不写逐次操作日志。
- 状态使用：设计中、实施中、阻塞、待接续、完成、取消。准备完成仍可保持设计中，接管后改为实施中；验收不足不得标完成。
- 已确认事实注明依据；推测、未验证内容和待决定的问题单列。用户未确认的建议不能写成决定。
- 必要检查、失败后的修复与复验照常执行。首次实际验证时创建 `.docs/{task}/evaluation.md`，统一记录方法、命令、环境、日期、适用代码或资料状态、逐项实际结果、验收结论和限制；尚未验证时仅在任务中写未执行。已有来源按需引用，无需每次新建证据文件，不能填预期结果充当通过。
- 有未提交修改时同时注明工作目录、分支及相关改动文件；提交号不代表工作目录完整状态。无 Git 则注明文件版本或日期。
- 默认长期保留当前 tasks.md、首次验证后形成的 evaluation.md 和验收后生成的 report.md，handoff.md 仅在明确交接时生成。tasks.md 保留验收标准及简短状态、阻碍，执行细节与结果统一链接 evaluation.md。正式测试、业务统计和实际产物留在约定位置，不复制完整内容。
- evaluation.md 只维护当前有效记录，以及仍影响排查的失败和未验证项；修复、需求或版本变化后更新对应记录。重复测试、下载进度、临时审查和文档自检记录默认为临时材料，不累计每次重试。清理须遵守用户授权及文件安全规则，不自动删除已有材料。
- 验证脚本只有在后续确实复用时才作为正式工具保留，放在项目约定位置；执行过一次不构成长期保留理由。
- 只有用户或任务验收明确要求详情或完整审计时，才长期保存过程附件并提供入口。长日志的存放约定仅适用于需要保留的日志，不要求生成或永久保存全部日志；多个验证过程共用 evaluation.md。验收记录及附件按验证、调试、审计或复验需要读取。

## 交接与恢复

- 只在换对话时创建 handoff.md，记录实际位置、暂停点、未提交修改、阻碍、未验证判断、旧方案残留和下一步；引用 tasks.md，已有验证链接 evaluation.md，不复制要求、命令、验证表或通过数量。
- 交接后任务标待接续，原维护者停止写入。接续者核对实际文件后记录接管、恢复实施中，并将交接标已接续，填写接续者和时间。
- 交接和验证可能过时；不同代码副本必须实际取得需要的文件。没有交接时，从当前任务及实际文件恢复状态，不把猜测写成事实。

## 完成与长期知识

- 实施对话依据 evaluation.md 核对当前要求及有效证据；验收通过后自动生成 `.docs/{task}/report.md`，不需要再次调用 Skill。报告列明成果概述、成果入口、重要变化、使用限制和知识更新，并链接 evaluation.md；验证方法、摘要、通过数量及验收结论只放在验收记录中。业务和研究结果仍属于成果。
- tasks.md 完成后保留当前要求、验收标准、状态和简短成果结论，分别链接 report.md 和 evaluation.md；业务产物仍使用任务指定位置。
- 实施对话读取 knowledge/AGENTS.md 后，自动更新已核实的跨任务事实及索引。没有新事实就注明无需新增，不创建空文档。
- 与既有决定冲突时不擅自覆盖，列出依据及影响。核对证据记入 evaluation.md；影响验收则保持阻塞，不生成完成报告；非阻塞冲突对成果使用的影响列入报告限制。
- 任务完成后保留原目录。重新打开时核对 evaluation.md 的适用状态与实际文件；要求或文件变化时将受影响的验收记录标为待复验，更新验证及成果报告，不把旧证据当作新结果。缺少可核实依据时按未验证处理。
